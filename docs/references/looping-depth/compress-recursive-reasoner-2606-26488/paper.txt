B.1   Sequence-Length Dependent Quantization Penalty
All rows in Table 6 were compiled through the Qualcomm AI Hub QNN execution provider
(libQnnHtp.so) targeting the Hexagon processor; no row falls back to CPU execution. Compilation
used enable_htp_fp16_precision=1, so graphs labeled “FP32” execute in FP16 on the Hexagon
vector engine (HVX), while INT8 graphs execute on the HTP tensor units with quantize/dequantize
(QDQ) boundaries at node interfaces.
  The benchmark reveals a counter-intuitive result: while static INT8 quantization accelerates the ARC-
AGI-1 and Maze-Hard models, it actually leads to a latency slowdown for the Sudoku-Extreme model
per step (from 11.38 ms to 27.23 ms on the S24). This behaviour is a classic small-matrix INT8 penalty
governed by the sequence length (T ):

• Compute-Bound Regime (ARC & Maze): ARC and Maze operate on a sequence length T = 900.
  At this scale, the weight projection matrices are large (900 × 512 by 512 × 2048), which translates to
  heavy arithmetic compute (∼187 GFLOPs/step). Moving this workload from the HVX FP16 pipeline to
  the HTP’s INT8 tensor units reduces execution time significantly, easily overriding the fixed dispatch
  and QDQ overhead.

• Overhead-Bound Regime (Sudoku): Sudoku has a sequence length of only T = 81 (97 with padding
  and embeddings). The matrix multiplications are tiny (e.g., 97 × 512 by 512 × 2048), requiring only

                                                        12
    ∼25 MFLOPs/step (7,500× less compute than Maze). A 97 × 512 matrix multiplication requires
    only ∼100K multiply-accumulates, which is too small to saturate the INT8 parallel execution blocks.
    Consequently, the fixed overhead of the Quantize/Dequantize (QDQ) operators—which convert tensors
    back and forth at every node boundary—dominates the execution time. While the FP16-on-HVX model
    runs in a single, unbroken compiler-fused pipeline in 11.38 ms, the INT8 model is penalized by a
    constant ∼25 ms invocation and marshalling overhead.

   Sudoku also relies on token-mixing MLP layers (mlp_t layers of 388 KB/194 KB). These represent
extremely small matrices. The Qualcomm Hexagon tensor processor has a minimum efficient tile size
threshold; matrix dimensions below this limit fail to trigger accelerated execution paths and fall back to
slower scalar execution, further exacerbating the INT8 penalty.
   The crossover point where static INT8 quantization becomes beneficial for this recursive transformer
architecture on mobile chipsets is approximately T ≈ 200–300. Below this threshold, FP16-on-HVX
execution remains faster.

B.2    Static vs. Dynamic Quantization
Dynamic quantization preserves full-precision accuracy on every task. Static quantization does not, and
Sudoku-Extreme recovers only under selective operator exclusion: leaving activation and carry-state
updates in FP32 and quantizing only the MatMul/Gemm weights. The trade-off matters for deployment:
dynamic quantization is the robust out-of-the-box path for recursive models, but NPU accelerators require
static, pre-allocated tensor boundaries, so on-device execution inherits the static path and its operator
exclusions (§B.1). We report this trade-off qualitatively; per-task accuracy under the static path was not
separately measured.

H    Architecture Ablation: MLP-Mixing vs. Attention
To separate architecture from task precision we evaluate three recursive architectures on the same task
(Sudoku-Extreme) under an identical harness (N =256, 16 ACT steps, no TTA; Table 15). TRM-MLP-
Mixing and TRM-Attention are the same model family at the same full-precision accuracy (73.8 vs.
73.1% puzzle exact), differing only in the token mixer; HRM (Wang et al., 2025) is a different recursive
architecture (separate high- and low-level modules, attention-based). Under naïve INT4, TRM-MLP-
Mixing collapses to 10.2% while both attention architectures retain their accuracy. Since TRM-Attention
matches TRM-MLP at full precision, this is not an accuracy-headroom effect—the INT4 fragility is
specific to MLP-mixing, not the task. The carry-trajectory fidelity diagnostic grades all three correctly
(0.35 / 0.87 / 0.98), confirming it generalizes across recursive architectures.

I   Carry-State Diagnostic: Full Data
We measure two carry-state quantities, computed by hooking the shared reasoning module across all
recursive calls within one inference pass. Both are computed on real test puzzles (Maze N =64, ARC
N =32, Sudoku N =256); the ARC and Maze checkpoints are the public TRM releases, the Sudoku
TRM-MLP checkpoint is a community reproduction (see checkpoint provenance, §O), and all numbers
below are reproduced from those checkpoints.
Consecutive carry similarity (single-model). The mean cosine similarity between consecutive carry
states (Table 16) is task-specific but insensitive to compression: it is essentially identical under FP32,
INT8, and INT4 on every task (changes ≤ 0.064), and is therefore a weak failure signal. We report it for
completeness; the diagnostic below is the one we recommend.
Carry-trajectory fidelity (vs. full-precision reference). The recommended diagnostic is the cosine
similarity between the quantized model’s final carry state and the FP32 model’s final carry state on the
same input—how far quantization pushes the reasoning trajectory off the full-precision path (Table 17). It
requires only the FP32 reference (available before deployment) and no task labels. Unlike the consecutive
signal, fidelity is graded and monotonic with severity: it stays ≈1.0 wherever INT4 is harmless (Maze,
all INT8) and falls in proportion to the accuracy damage—moderately on ARC (0.69, −10 pp) and
catastrophically on Sudoku (0.35, −64 pp). Per-channel calibrated INT4 recovers fidelity in lockstep with
accuracy, so the diagnostic predicts both failure and recovery.
Calibrated INT4 recovers Sudoku. Measured under an identical evaluation harness (N =256, 16
ACT steps, no TTA), naïve per-tensor INT4 collapses Sudoku to 10.2% puzzle-exact while per-channel
calibrated INT4 recovers to 71.9% (vs. 73.8% FP32 under the same harness)—i.e., the catastrophic INT4
result is specific to naïve quantization, and the 4 MB MCU target is reachable with calibration (Table 18).

K    Linear-Attention Approximation (Maze)
Replacing softmax attention with ELU feature-map linear attention (O(n) vs. O(n2 )) on Maze illustrates
the same cell-vs-puzzle split as quantization: the swap preserves token-level accuracy but destroys
puzzle-level reasoning. Evaluated at H=3, nsup =1 (hence the 78.50% baseline rather than the full-depth
86.80%): zero-shot, cell accuracy holds at 87.3% while puzzle-exact falls to 0.00% (from 78.50% /
99.40%); brief retraining (200 steps) recovers cell accuracy (87.5%) but not puzzle-exact (0.00%). This
is a third intervention—alongside pruning and distillation—under which local prediction survives while
global constraint satisfaction collapses. Sudoku-Extreme (MLP-mixing) has no attention layers and is not
applicable.

M    Energy per Inference
Estimated energy follows the FLOPs counts under a Cortex-M55 power model (∼1 mJ/GFLOP): ARC-
AGI-1 at full depth (∼3,000 GFLOPs/puzzle) draws ∼3,000 mJ/puzzle, versus ∼500 mJ at the reduced
configuration (H=1, nsup =8). Sudoku-Extreme (∼256 GFLOPs at default depth) draws ∼256 mJ/puzzle.
These are analytical estimates under the same FLOPs-based model. The model is precision-blind—it
assigns no separate energy-per-operation term to FP32 vs. INT8—so the 6× energy saving follows entirely
from the 6× FLOPs (cycle) reduction, not from quantization.

N    Context-Length Truncation

Truncation is destructive on every task (Table 22): halving the sequence length takes Maze and Sudoku to
zero and costs ARC nearly ten points. There is no cheap context shortcut—the full window is load-bearing.

O    Implementation Details
Checkpoint provenance. The Sudoku TRM-MLP checkpoint is the alphaXiv community reproduction
of TRM, whose model card reports 79.37% puzzle exact vs. 87.4% in the original paper. Our Sudoku
claims are therefore relative comparisons between compression variants evaluated at matched checkpoints,
not absolute-accuracy claims against the original release.
Quantization. INT8 and INT4 PTQ were applied using bitsandbytes v0.41 (Dettmers et al., 2022)
with load_in_8bit=True and load_in_4bit=True respectively. Per-channel calibration for
INT4 calibrated used 128 calibration puzzles drawn from the training set.
Carry-state extraction. sh was computed by registering a forward hook on the carry-state update
function gϕ to capture Zh at each outer cycle. Cosine similarity was computed token-wise and averaged
across the sequence dimension and across all puzzles in the evaluation set.
QAT. The headline QAT runs (§4.6) initialize from the calibrated-INT4 checkpoint and fine-tune for
1,000 steps at batch 32, under cross-entropy and token-distillation objectives at learning rates 10−5 , 10−4 ,
and 10−3 , with the deep-supervision ACT loop. A shorter probe (100 steps, lr=10−5 , cross-entropy, batch
4, from the naïve INT4 checkpoint) is the held-out run cited in §4.6. Training and evaluation used the
Modal cloud platform.
ONNX export and edge deployment. Models were exported to ONNX format using
torch.onnx.export for deployment via ONNX Runtime and Qualcomm AI Hub. The ONNX
export produces a single-step model (TRMBackboneStep) that executes one H-cycle step, with the
outer recursion loop managed by the inference harness.
