# Agent Note: Gated TUL — a self-supervised span-length gate

Status: proposed

## Problem

TUL is merged but off by default, because a bake-off has to decide what ships. One arm
that has never existed in MORPH is the one the predecessor project (`00DeepNet/coconut`)
was built around: a **gate** that lets the model choose how many tokens the next span
covers, `k = 0` meaning "loop again". It did not cross over because it was developed
against an already-pretrained, frozen decoder, where the only signal available for
"decode to the period versus stop short" was a reward. Wolfe's question was whether the
same mechanism has a pretraining-compatible form.

It does, and it is simpler than the predecessor's. In pretraining **we own the
segmentation**, so the correct span length is already computed causally by
`BoundaryRule.cut`. The gate becomes plain supervised regression against a label the
data already contains. No reward, no RL, no policy-gradient stage.

## Proposal

Build two arms, specified strictly in [docs/tul-gate-spec.md](../../../../docs/tul-gate-spec.md):

- `TUL-gate` — a length head on the slot state, a **budget-conditioned coda**, and a loader
  augmentation that truncates spans (which also produces the mid-unit starts the spec's
  §3.1 asked for; they are two halves of one edit, so there is one knob). Loop depth stays
  per-slot Poisson; the coda is teacher-forced on the realised length.
- `TUL-halt` — the SAME run, scored a second time with the gate choosing each slot's depth.

Pre-registered before either runs: `TUL-halt` does not beat `TUL-gate`, and fixed depth
ships. The falsifier is written down in the ledger.

**Status 2026-08-22: the mechanism is built and the bake-off is running**
(`ignore/perf/gate_bakeoff.sh`: `tul_gate` → `tul_a1` → `tul_a1r`, sequentially). This note
stays in `proposed/` because the decision it records — does the gate ship — is what the
bake-off is for. `pytest tests/` → 189 pass; every §9 invariant has a test and each was
mutation-checked (15 deliberate breakages, 15 caught).

### What building it changed in the design

Four amendments, all found before any arm was scored, all recorded in spec §13. Two are
worth repeating here because they were real defects, not clarifications:

1. **The label was the wrong span.** The spec said "this slot's span length". Slot i sits
   AFTER span i, so causal attention lets it condition only span i+1 — which is the span
   generation asks it about. As specified, the gate would have been a readout of a length
   the slot already contained and that generation could never use. The label is now
   `len(span i+1)`.
2. **The `k = 0` half of the target destroys the length half.** The per-slot depth is a
   Poisson draw independent of the input, so no head can know which iteration is its last;
   the optimum of "emit 0 until the last iteration, then the length" is the HAZARD times
   the mean length. At `mean_depth` 6 that is `k = 5` at the iteration a fixed-depth
   generation reads. Measured on the 5090 at step 40 and 120: `k = 5.00` and `5.68` against
   gold `18.98` and `19.58` — the predicted table row to the integer. The model was already
   Bayes-optimal for the objective we wrote, and that optimum is not a length.
   `gate_train_zeros` now defaults False; the stop decision belongs in the separate head
   that §12 parks. This makes the §7 prediction about `TUL-halt` true *by construction*
   rather than by experiment, which is a stronger result and is credited as such.

The other two: `gate_k_max` (40) is the regression denominator and deliberately exceeds
`span_cap` (32), because 24.5 % of real OpenWebText labels are a capped span and would sit
on the sigmoid's asymptote; and the gate readout runs outside the checkpoint rather than
threaded through it, which keeps the "return value, not side channel" guarantee while
giving the ~28 % of slots whose depth lands in the frozen BPTT window a gradient for their
label.

`gate_lambda` is 1.0 — the predecessor's `lambda_g` (`coconut/tul/config.py:81`). No MORPH
ablation has picked a value; the 6-or-8 figure remembered in conversation does not appear
anywhere in that repo's configs or code.

Three findings from mining the predecessor drove the design (all pinned to lines in
that repo, see spec §2):

1. Its gate was trained by **supervised Huber regression**, not RL. The RL stage was
   later, thin, and moved the Llama numbers by nothing (EM 0.18 → 0.18). The
   self-supervised framing was the original design, not a simplification of it.
2. **The decoder was never told `k`** — no embedding, no prefix, no mask; `k` was a
   Python loop bound at inference. So the model was never able to trade "reach the
   period" against "be accurate", because the two halves never had to agree. The
   budget-conditioned coda is the fix and is the substantive new mechanism here.
3. **Partial spans were never trained.** `phase_jitter` was implemented and all 15 saved
   run configs had it at 0.0. Without it, the first short guess at generation is out of
   distribution.

### What this costs

- **A live invariant changes.** `runtime-invariants.md` §6b states "slot core states have
  no loss". `TUL-gate` puts one there. The exception is deliberately narrow — a scalar or
  discrete **readout** is allowed, a vector **regression onto a target representation**
  stays forbidden — and spec §9 makes it a tested distinction rather than an assumption.
  The §6b citation set (MegaByte, H-Net, LD4LG, Pred-Sent, Block Transformer §4.2) is
  about reconstructing the latent, not reading a scalar off it, but this is exactly the
  class the ledger already flags as risky, so it is measured, not asserted.
- **Teacher forcing leaks.** Conditioned on the true length, the coda sees an easier token
  task than it will meet at generation. End truncation blunts it; scheduled sampling would
  close it and is specified but not built. Generation metrics, not val CE, are what expose
  this — so they are required from run 1.
- **The halting arm's ceiling is low and we should say so up front.** Per-slot depth is a
  masked update and frozen slots are still computed, so variable depth saves no compute in
  batched inference. Its case rests entirely on quality, and there is no cheap label for
  where thinking is needed.

## Alternatives considered

- **PonderNet / ACT halting.** Rejected for round 1. A true PonderNet needs the loss at
  every candidate halting step, which means running the coda — over all positions — `T`
  times per step, and it needs a readout on the slot state that this project's invariants
  restrict. Large bill for an arm we predict loses.
- **Grading the `k = 0` run-length against the Poisson draw** (Wolfe's first
  construction). The draw is independent of the input, so the head converges to the
  hazard and, with `mean_depth 6` and the measured 19.9-token mean span, halts at
  iteration 2 emitting one token — at a converged, low gate loss. Arithmetic in spec §7.
  Round 1 therefore trains the zeros and does not let them drive generation.
- **A content-derived depth target** (halt when the slot state stops moving). Still open;
  it is the natural successor if `TUL-halt` shows the mechanism is worth steering.
- **Computing sentence complexity to manufacture a depth label.** Rejected: it costs more
  at train time than the depth it would save at inference.

## Acceptance criteria

1. `gate_lambda = 0`, `gate_budget_cond = False` is bit-identical to `TUL-A1` — loss,
   parameters and gradients `torch.equal`.
2. Every invariant in spec §9 has a test, and each is mutation-checked: break the code,
   watch the named test go red.
3. `audit_travel` refuses a run whose gate parameter group provably cannot move within the
   step budget, and `gate_separation` plus the hazard curve are logged from the first eval.
   The predecessor lost an entire ladder to a gate whose bias sat 57× short of its required
   travel, with `gate_separation` defined and never measured.
4. A results note is written for `TUL-gate` and `TUL-halt` whether they win or lose.

Status of each: 1 ✅ (`test_lambda_zero_and_no_budget_cond_is_bit_identical_to_a1`);
2 ✅ (15 mutations, 15 caught); 3 ✅ — the audit refused a run in practice before any arm
started, which is how the asymptote defect above was found; 4 pending the bake-off.

## Risks

- The length head is an auxiliary loss on the latent, the class Block Transformer §4.2
  reports as harmful. Mitigation: it is an arm, with `TUL-A1` as the paired reference.
- The gate can converge to a low loss while being useless (the predecessor's
  `loss_g 0.00066` with a pinned bias). Mitigation: acceptance criterion 3.
- Truncation changes the span distribution the model sees. Mitigation: `truncate_p` is a
  loader key with a sweep, and the fraction of spans ending on a boundary is logged.
