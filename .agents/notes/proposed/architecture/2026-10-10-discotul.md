# Agent Note: DiscoTUL and LX-DiscoTUL, DiscoLoop re-embedding between slot-loop passes

Status: proposed

## Problem

The slot loop passes one continuous state from pass to pass. DiscoLoop (Fu et al. 2026,
arXiv 2607.00341) reports a specific failure of that hand-off in looped transformers: after
pass 1 the hidden state already decodes the bridge token of a two-hop question with
probability near 1, yet it sits at cosine about 0.3 to that token's embedding, so the next
pass's retrieval (which works in embedding space) cannot use it. Their fix re-embeds the
state through the tied LM head between passes. On their toy two-hop task out-of-distribution
accuracy went from 8.3 % to about 100 %. In a 440M, 20B-token pretrain they trailed the plain
loop until about 13B tokens and then led by about 0.01 loss.

MORPH has not tried it. The nearest thing on the tree, `tul.pseudo_k` (the snap arm), writes a
span-token mixture into the coda's prefix AFTER the last pass, never between passes. Wolfe
(2026-10-10, phase-2 tracker D2): test it as an alternative to LXTUL, two ways, build now, run
after the optimization work.

## Proposal

`tul.disco` (`morph/model/tul_disco.py`, one site in `MORPHTransformer._tul_core`,
`_disco_term`). At the INPUT of every slot-loop pass `t >= 1`:

    Phi(h)   = sum_v softmax(head(h) / tau)_v W[v]
    _h_in   += alpha * RMSNorm(Phi(h))          on the cells whose depth continues into pass t

Decisions, each with its reason:

1. **Site.** The term is added to `_h_in` after the fan trigger and before the gain hinge,
   only on cells with `depths > t` that are valid. A finished cell keeps serving keys and
   values from its frozen carrier (runtime-invariants §6b), so it must not get a term.
   Nothing is added after a slot's last pass, so the exit (what `W_prefix` and the coda read)
   is the raw output of that pass: the paper's "last pass ungated". `h`, which the
   fixed-point term, the recurrence gate and `db_traj` read, never holds the term.
2. **Read.** The carried cell at the top of the pass: the previous pass's output after the
   slot-cell pass norm, and on the latent-selected loop after the reset to the winner. The
   Hyper-Connection stream mean is taken by `_readout` itself.
3. **Logits.** The model's own token head, by its own functions: `_readout` (stream mean,
   `lm_mixer`, `final_norm`) then `embed.attend` with the structural slot id at `-inf`. The
   head has no logit scale or softcap. The pointer mixture is not part of the read: it is a
   copy head over earlier TOKEN states, which a cell does not have. `embed.attend` gained a
   `detach_table` argument (default False, the head as before) so the read calls the head
   instead of copying it.
4. **Table gradient.** `tul.disco_detach_table: true` (default). An undetached auxiliary head
   through the tied table diverged arm v1a by step 2800 (memory note
   `morph-lm-head-is-weight-tied`). The gradient still reaches the loop through the logits and
   `lm_mixer` / `final_norm`, which the token head shares.
5. **Bridge.** `soft` (the paper's exact form), `topk` (softmax over the top `disco_topk`
   logits, 128; the paper's LM form and the arms' default), `hard` (forward = the argmax row
   exactly, backward = the top-k mixture's gradient). The soft bridge shrank the norm to 0.27
   in DiffusionBlocks and the argmax row fixed generation there (memory
   `db-bridge-is-the-bug`); the RMSNorm below fixes the norm, not the direction.
6. **Norm.** `attention.RMSNorm` with its learned gain, init 1.
7. **Gate.** `learned`: `sigmoid(<w, Phi_n> + b)`, `w` init 0, `b` init `disco_gate_bias` 0.0,
   so alpha is 0.5 at step 0 and the gate starts OPEN (the snap arm's gate started at 0 and
   never opened). `fixed`: the constant `disco_alpha`.
8. **Streams.** The d-vector is broadcast into every Hyper-Connection stream, one full copy per
   stream (`_apply_injection`, the rule for every single-stream term including
   `DiagonalInjection`'s per-stream source), so the read state moves by exactly the term. Full
   width, as the paper and the fan trigger add it, not `DiagonalInjection`'s 320-channel
   context slice.
9. **LX-DiscoTUL.** `_lsel_pass` resets every cell of a slot whose depth reaches pass `t` to
   the winner (`reset_to_winner`, mask `depth > t`, the same mask as the term). So the four
   cells entering pass `t` are bit-equal on every slot that gets a term; they differ only
   inside the pass, through their own injection source and register term. Phi is computed
   ONCE per slot, on cell 0 (the winner), and broadcast to the four cells. On a fan without
   the selection the cells differ and each gets its own read.
10. **Gain hinge.** It probes the pass at `_h_in`, which now holds the term, so the hinge
    measures the map at the input the pass actually got. The term is a constant inside the
    hinge's finite difference (the trigger's and the grad-pass feature's reading).
11. **RNG.** Every parameter is a constant at construction (ones, zeros, a constant bias), so
    no RNG is drawn and the base weights equal the same-seed model without the key.
12. **Graph capture.** Fixed k, a fixed pass count under `graph_safe`, masks instead of gathers,
    no host read at train. The eval readings (one `torch.unique` per pass) run at eval only.
13. **Decode.** The cached generator refuses `tul.disco` (one entry in `_check_supported`);
    the eager `generate_tul` runs it.
14. **Eval readings** (diagnostics, never a verdict), per pass `t >= 1`, as `val/disco_*_t{t}`:
    gate mean, the bridge distribution's entropy and top-1 probability, the number of distinct
    argmax tokens over the number of rows (the unigram-mean collapse check: the slot carrier
    was 98 % one slot-shared vector before), and RMS(term) / RMS(carried cell).

Arms (configs, all composed and diffed in `tests/test_tul_disco.py`):

| Arm | Config (fast / eager twin) | One factor against |
|---|---|---|
| one-cell control | `tul_onecell_pointer_fast` / `tul_onecell_pointer` | the winner without the fan |
| DiscoTUL | `discotul_fast` / `discotul` | the one-cell control |
| LX-DiscoTUL | `lxtul_disco_fast` / `lxtul_disco` | `lxtul_pointer_fast` / `lxtul_pointer` |

The one-cell control is composed from the strict ruler (a Hydra child cannot delete a
parent's fan keys) and sets back every non-fan piece of the winner: fixed-point 0.1, the cell
RMSNorm, the pointer head (4), the span decoder, the hinge, and `prefix_k 4`, the winner's
coda width, so a CE difference against LXTUL is not prefix width. Two speed keys of the
winner's fast path cannot apply at one cell and are refused at build: `tg_fused_attention`
(the kernel implements the register core only) and `slot_compact` (needs `slot_cells > 1`
and the fused kernel). The four fan keys go with the fan.

## Alternatives considered

- **Add the term after every pass, including the last.** The paper gates the last pass off
  because the prediction reads `H(K)`; in MORPH the exit feeds `W_prefix` and the coda, and a
  term there would make the exit an embedding-row mixture instead of the loop's state. Not
  built.
- **Add the term to finished slots too.** Their keys and values serve later slots at every
  later pass; a term there changes what those slots read, through a channel that has nothing
  to do with the re-embedding question.
- **Read through `_readout_per_stream` or a private norm.** Either would make the read a
  different head from the one the coda's tokens are scored with. The paper's point is to use
  the model's own decoder.
- **Undetached table.** Measured to diverge once on this tree (v1a); kept as a knob
  (`disco_detach_table: false`), not the default.
- **Inject into the context slice only (`DiagonalInjection`'s channels).** Hands the next pass
  320 of 1024 channels of the embedding row; the paper's add is full width.
- **Phi per cell on LX-DiscoTUL.** Four reads of four bit-equal inputs; the per-slot read is
  exact (pinned) at a quarter of the head GEMM.
- **Gate starting closed (`b` very negative).** The snap arm's zero-init gate never opened; a
  closed start can also hide a broken term behind an inert gate. `disco_gate_bias` exists to
  try other starts.

## Acceptance criteria

Build (this change, CPU tests in `tests/test_tul_disco.py`):

- Off builds nothing; on draws no RNG and leaves every base weight equal to the same-seed
  model without the key.
- `disco_gate: fixed, disco_alpha: 0` gives a loss, every base gradient, eval logits and eval
  loss `torch.equal` to the base, one-cell and latent-selected, dropout 0.0 and 0.1.
- The detached table puts no gradient on vocabulary rows absent from the batch.
- Finished slots and pass 0 get no term; the exit is the raw output of each slot's last pass.
- Each bridge matches a direct reference; the in-model term matches an independent reference.
- Every test above fails under a sabotage of the property it pins.
- The three fast configs run 30 steps under `graph_step` on the 5090 (smoke) and have a
  ms/step and peak-memory reading against `lxtul_pointer_fast` (bench).

Experiment (tracker D2b, after A and C, with a prereg before any run): K1-K6 and val CE of
DiscoTUL against the one-cell control and of LX-DiscoTUL against `lxtul_pointer_fast` at 5k,
plus the `val/disco_*` readings per pass. The tracker's caveat holds: the paper's gain showed
after 13B tokens and our 5k is about 31M, so a 5k web-text CE reading is expected to sit
inside our noise; a multi-hop task (the Parcae testbed) is the fair test of the mechanism.

## Risks

- **The slot cell has no trained token readout** (`emit_weight: 0`). Its logit lens may give a
  slot-shared unigram mean, so Phi would be one vector for every slot (the carrier constant
  again). `val/disco_distinct_frac_t{t}` reads this directly; a value near 1/n_rows means the
  term is a constant offset.
- **The term changes the loop's operating point.** At alpha 0.5 the term's RMS is half the
  normed cell's at step 0 (read 0.5 on the tiny fixture). The gain hinge sees it as a constant
  input, so it does not bound the term's own contribution to the pass-to-pass map.
- **Cost.** One `[rows, d] @ [d, V]` head GEMM plus a top-k per pass per slot: about 4 block
  applications per slot per pass at V 49169 (tracker D2). The one-cell arms also run without
  the two register-only speed keys. Measured so far (2026-10-10): the 30-step `graph_step`
  smokes of all three fast configs ran (3 eager steps, 27 replays each); the baseline
  `lxtul_pointer_fast` benched at 230.1 ms/step (420 steps, the phase-1 bench). The three
  arms' ms/step is not measured yet: the GPU was put on hold (UPS alarm) before their bench.
- **Graph capture.** The first `graph_step` smoke died at capture: masking the slot id with
  `index_fill(torch.tensor([slot_id], device=...))` is a host-to-device copy, which capture
  refuses. The mask is now a scalar fill on the logits' slot column.
- **`soft` memory.** The full softmax `[rows, V]` fp32 is saved per pass for the backward
  (~75 MB per pass at 384 rows); `topk` and `hard` save `[rows, k]`.
- **`lm_mixer` / `final_norm` get gradient from the read.** They are shared with the token
  head; only the table is detached.
