# Agent Note: LX-Fan — the enumerated loop code on the write-all fan's distinct cells

Status: proposed

## Problem

Two slot-loop mechanisms each hold a measured result, and the tree refused to run them
together.

- **LX** (`tul.code_enum_k: 4`, [2026-09-23-provable-loop-contribution.md](2026-09-23-provable-loop-contribution.md)):
  K enumerated codes re-added at every pass, the exact per-span mixture over the K
  rollouts as the token loss, the per-span Bayes read at deploy. Its recipe, fp01
  (`tul_slot_spandec_strict_e4probe_fp01`), trails the plain model by 0.265 nats at 5k.
- **The write-all fan** (`tul.fan_k: 4`, `fan_mix: all`, [2026-09-20-fan-write-all-wta.md](2026-09-20-fan-write-all-wta.md),
  [2026-09-19-lxtul-fan-streams.md](2026-09-19-lxtul-fan-streams.md)): four cells per slot, each
  pooled from the span by its own learned query, looped, and written 1:1 into its own
  prefix cell. Arm a2 (the fan with fp01's fixed-point term) closed 0.047 nats of that gap
  (+0.218 against fp01's +0.265), and a1 (four projections of one state) did not, so the
  lever is distinct content per cell, not the cell count
  ([2026-09-26-slot-channel-arms-ab.md](../../../../lab/experiments/successes/2026-09-26-slot-channel-arms-ab.md),
  [2026-09-26-slot-channel-width-and-reach.md](2026-09-26-slot-channel-width-and-reach.md)).

`TULConfig._check_code_enum` refused `fan_k > 0` and `slot_cells > 1`, and
`_check_spandec_parallel` refused `fan_k > 0`. So a2 had to drop the code, and the one
channel that moved the gap could not carry the loop's code. Design D1 of the 2026-09-26
TUL v2 review (`/home/wolfe/morph-scratch/tulv2/opus.md`, private) ranks this combination
first.

## Proposal

**The combination.** `code_enum_k = K > 1` on the write-all fan with M cells. The slot loop
runs on the K-fold rollout batch as LX always does, on the fan's cell axis (`[K*B, S*M, n,
C]`). Rollout k adds `r * rms_cell(f(h)).detach() * u_k` to EVERY cell at the end of every
pass. This is the existing `_tul_core` code site: under the register the layout it reads is
per cell, so the code is sized by each cell's own RMS and no new term exists. That gives K x
M loop streams per slot (16 at M = 4, 24 at M = 6). The coda reads all M cells of every
earlier slot under each code; the token loss is LX's exact per-span mixture
(`_enum_mix_losses`), and the label-free forward is LX's Bayes read
(`_enum_mixture_logprobs`). Neither function changes.

**What changes in the code.**

| Where | Change |
| --- | --- |
| `tul.py::_check_code_enum` | The fan refusal is lifted for `fan_mix: all` only. A mixing or select fan, `fan_all_wta_lambda > 0` and `fan_seed_noise > 0` are refused by name. The bare register (`slot_cells > 1` without a fan) stays refused. |
| `tul.py::_check_spandec_parallel` | The fan refusal stays; its reason now says why (below). |
| `tul.py` fan block | `fan_select_eps` is refused when set away from its default at `fan_all_wta_lambda: 0` (a silent no-op there). |
| `transformer.py::_tul_core` | Under the rollout batch the register pools the prelude ONCE on the base rows and is tiled rollout-major, as the depth draw is. The single-rollout path is unchanged. |
| `transformer.py::_tul_fan_all` | `fan_all_wta_lambda: 0` builds no term and runs no coda pass. Before, it ran the K no-grad passes and one grad pass and multiplied the term by 0. |
| `transformer.py` fan repulsion | Under the code, the epi term's ridge is `fan_epi_ridge * K`. K duplicated seeds at ridge `lam * K` give exactly the base batch's ridge fit on the rollout-mean deviations. |
| `transformer.py::_tul_fan_oracle(n_rollouts=)` | Every span CE (each stream's, and the shipped write's `mixed_ce`) is read as the per-span mixture over the K rollouts, on the base rows. |
| `transformer.py::_enum_exit_stats` | Reads the written cells, not their mean. |
| `tul_generate_cached.py::_check_supported` | Refuses the fan by name (it already refused `slot_cells > 1`). The eager `generate_tul` runs LX-Fan. |
| `tul_setup.py` | An `LX-FAN ON` banner; the fan banner says what WTA 0 does. |

**The cell count is one knob.** `tul.fan_k` (it aliases `slot_cells`), with `prefix_k:
${tul.fan_k}` in the parent config, because `fan_mix: all` needs `prefix_k == fan_k`.
Configs:

- `tul_slot_spandec_strict_lxfan4_fp01.yaml` (wandb `lxtul-lxfan4-fp01`) is fp01 plus the
  fan minus the probe head. The keys are `fan_k 4`, `prefix_k ${tul.fan_k}`, `fan_mix all`,
  `slot_cell_init distinct`, epivol 0.1 over passes 1-2 with a2's epi settings,
  `fan_all_wta_lambda 0`, and `spandec_parallel{,_detach} false`. It runs 5000 steps
  (fp01's, inherited).
- `tul_slot_spandec_strict_lxfan6_fp01.yaml` (wandb `lxtul-lxfan6-fp01`) is lxfan4 with
  `fan_k 6`. LaDiR encodes a sentence in about 6 latents; MORPH writes 2 (fp01) or 4 (a2).

The rest is fp01's recipe, unchanged: fixed-point term 0.1, row gain hinge 0.98, tail
hinge 100 @ 1.1, strict geometry, token-state dropout 0.15, no teacher-forced decoder.

**The fan-only terms: what each one does here and why.**

- **Winner-take-all: dropped (`fan_all_wta_lambda: 0`; refused at > 0 under the code).**
  1. It is a second credit assignment. It picks a winner stream per slot and trains that
     stream alone, beside the per-span mixture, which already assigns credit over the K
     codes by posterior.
  2. It trains the coda on a write geometry (one cell live, the rest blank) that the
     deployed read never sees. The select arm filed that train/deploy mismatch.
  3. On the K-fold batch it costs M no-grad coda passes plus one pass with grad per step:
     24 base-batch coda passes at M = 6.
  4. Its batched no-grad pass stacks M*K*B rows under the rollout-shared dropout
     (`rollout_dropout.py`), which ties the masks of the wrong rows. Making that correct
     is surgery.

  D1 also scores the arm on LX's exact marginal alone.
- **epivol: kept (lambda 0.1, passes 1-2, as in a2).** D1's own named risk is the Thought
  Register collapse (rank 1.24 of 4). The codes do not oppose it: u_k is added to every
  cell of rollout k, so it cancels in the within-slot deviations the collapse lives in.
  Without WTA, epivol is the one thing left that keeps the cells apart. It is the one
  diversity term measured NOT gamed (rank 2.82 of 3,
  [2026-09-20-fan-epiplexity-diversity.md](2026-09-20-fan-epiplexity-diversity.md)). It
  reads the loop trajectory only, so it costs no coda pass.
- **The teacher-forced span decoder (`spandec`): off.** fp01 dropped it for the parallel
  head. On the K-fold batch it decodes K times (4.4 GB of a 20 GB step at B = 6, K = 4,
  measured 2026-09-23). It grades the cells' MEAN, which is not what the coda reads.
- **The detached parallel head: dropped (still refused with the fan).** It works without
  code surgery: under the write-all fan `h_slots` is the MEAN of the M cells and the head
  reads it. But the coda reads each cell 1:1, so the head's CE would describe an object
  no reader consumes. fp01's head reads the one exit state that `W_prefix` projects into
  both cells, so there it IS the channel. A head that reads M cells is a new module, and D1
  removes the head too.

## Alternatives considered

- **a2's recipe plus the codes (WTA 1.0, spandec true).** This is the closest one-factor
  partner of a2. It was rejected for the four WTA reasons above. It would also pay the
  K-fold spandec decode.
- **Drop epivol too, the literal "fp01 recipe otherwise".** Rejected: nothing would oppose
  the cell collapse. If lxfan's `fan/stream_rank_t*` holds without the term, a follow-up
  arm can take it out.
- **Size the code by the slot's RMS over its M cells.** Rejected. A quiet cell would get a
  code sized by its loud siblings. Per-cell RMS keeps LX's ratio meaning at every loop
  position, and it is what the existing code site already does on the cell axis.
- **Allow the mixing fans (mean / softmax / select) under the code.** Refused. They collapse
  the cells to one state BEFORE the coda, so the fan would be a width axis in front of the
  rollouts. The select fan also runs its own coda passes.
- **Leave the register on the expanded batch.** It is correct, but it does K times the
  pooling work on inputs the K rollouts share. Base-then-tile gives the same gradient.
- **Leave the epi ridge at `lam`.** Rejected. Each seed appears K times, so the fit would
  run at an effective ridge of `lam / K`, and the term would change its meaning with K.
- **Keep the oracle on per-rollout CE.** Rejected. Its `mixed_ce` would then be the mean of
  the rollouts' CEs, which is not the number the model is scored on. The oracle-minus-single
  gap would also be read in different units from `enum_ce_mix`.

## Risks

- **Cell collapse.** The code does not keep cells apart; epivol does, over passes 1-2 only.
  Watch `fan/stream_rank_t*` and `fan/vol_t*`. a2's pass-6 rank fell to 2.03 of 3 with WTA
  feeding one stream. Without WTA the shape may differ either way.
- **Cost, unmeasured.**
  - The coda runs on K*B rows at `L_total` 1280 (M = 4) or 1408 (M = 6), against fp01's
    1152.
  - The loop runs on K*B rows of S*M cells (256 or 384 per row at 64 slots, against
    fp01's 64).
  - The eval oracle replays the coda M times on the K-fold batch (24 base-batch coda
    passes per eval batch at M = 6).
  - lxfan6 may not fit at batch 6. The trace decides that, not this note.
- **Neither config is a one-factor arm.** Against a2 the differences are the code, WTA,
  spandec, fp01's two hinge keys, and the default `fan_select_eps` key. Against fp01 the
  differences are the fan and the dropped probe head. The pair of readings is the result.
- **The fan's CE instruments score the UNMASKED head.** `accumulate_span_ce` leaves the slot
  id its logit, and the token loss masks it. So `fan/mixed_ce` exceeds the model's CE on
  the same spans by the slot id's mass: 0.0098 nats on the tiny test model at init. This
  has held since the fan was built. Changing it would move a2's WTA term and break the
  fan's bit-identity, so it is named here, not changed. Compare `fan/*_ce` only with
  `fan/*_ce`.
- **WTA 0 changed meaning.** Before this change it ran the passes and charged 0; now it runs
  nothing (and consumes no RNG for the eps draw). No config ran WTA 0.
- **Decoders.** The cached and graphed decoders refuse LX-Fan. Only the eager generator
  runs it (tested on CPU at M = 4 and 6).

## Amendment 2026-09-26: the fan's winner-take-all is built under the code

Wolfe wants three credit arms tested: (a) LX-Fan as built above, (b) LX-Fan with a2's WTA
over the cells KEPT, (c) fp01's LX with hard credit over the rollouts
([2026-09-26-lx-hard-credit.md](2026-09-26-lx-hard-credit.md)). Arm (b) needs
`fan_all_wta_lambda > 0` under the code, which this note refused. It is now built:
`tul_slot_spandec_strict_lxfan4_wta_fp01.yaml` (wandb `lxtul-lxfan4-wta-fp01`) is lxfan4
plus a2's `fan_all_wta_lambda: 1.0` and `fan_select_eps: 0.05`, 5000 steps.

**The port.** `_tul_fan_all(n_rollouts=K)` runs a2's term on the K-fold rollout batch
with no change to its arithmetic:

- the winner is picked per (rollout, slot): the M cells of rollout k compete under code k;
- the grad pass writes each (rollout, slot)'s winner alone;
- the term is the token-weighted winner-alone CE over all K*B rows, which is the mean
  over the rollouts of a2's term;
- it folds as `fan_wta_weighted`, so train/loss stays the model's CE (a2's contract).

A per-SPAN winner shared by the K rollouts (picked on the mixture CE) was the other
candidate. It was not chosen. a2 had no code, so it never tied which cell carries a span
to anything. A shared winner would force one cell to hold the span under every code, and
the code conditions the loop that fills the cells. That constraint is new, and it would
change two factors at once. The per-rollout winner also keeps the two credits apart: the
mixture credits the rollouts by posterior, and the WTA credits the cells hard, inside
each rollout.

**How each refusal reason was handled.**

1. *A second credit assignment.* Accepted. It is the point of the arm, so it is
   deliberate here. The two credits act on different axes (rollouts: posterior; cells:
   hard, within a rollout).
2. *It trains the coda on a write the deploy read never sees.* Accepted, as in a2. The
   one-cell-alive write is a training-only geometry. It is the same mismatch a2 carried,
   and a2 is the arm whose lever this ports. The eval read is unchanged: all M cells
   under the Bayes read over the K codes.
3. *Cost.* Accepted. Per step the arm runs M no-grad coda passes of K*B rows (one per
   stream) plus one grad pass on K*B rows, on top of lxfan4. That is M + 2 coda passes of
   the model's own size, where a2 runs one batched pass of M*B rows and two of B rows.
   `/home/wolfe/morph-scratch/credit/mem_trace.sh` measures whether batch 6 fits. If it
   does not, the trace reports the largest batch that fits, and the arm's batch is not
   changed.
4. *The batched pass ties the wrong rows' dropout masks.* Fixed. The core and coda of a
   code model use `RolloutSharedDropout(n_rep=K)`. It draws a mask for the first 1/K of
   a pass's rows and tiles it K times. Under the code the table now runs ONE PASS PER
   STREAM on the rollout batch. Row (k, i, b) then gets its own pass's mask for (i, b).
   That mask is shared by the K rollouts of a row, as in every other LX coda pass. It is
   independent across streams (separate draws) and across rows, as in a2's pass. a2 at
   K = 1 keeps its one batched pass and is bit-identical. Stacked stream-major, row
   (k, i, b) would have drawn mask (k, b): each rollout a different mask, and the M
   streams of a rollout one shared mask. A rollout-major `[K, M, B]` stack also gets
   the masks right, and it was the first version built. It was replaced because it is
   M*K*B = 96 rows of eager strict-coda attention in one pass at batch 6. The
   `[rows, H, L, L]` fp32 score tensor alone is 5 GB per attention call at L 1280.

**Tests** (`tests/test_tul_lx_credit.py`, the arm-b half):

- lxfan4 and a2 match the e951498 pins at dropout 0 and 0.1. `pin_compare.py` also
  compares the full tensors.
- The pass count is M no-grad passes of K*B rows, then the grad pass and the coda. a2
  keeps one pass of M*B rows, then two of B rows.
- The table equals an independent per-stream sequential reference, and the grad pass
  writes each (rollout, slot)'s argmin. The winners differ across rollouts on the test
  batch.
- The mask test is on CONTENT, over all M table passes. With the codes zeroed, rows with
  equal input draw equal masks, and rows with different input draw different masks. A
  check on row positions alone cannot fail, because the dropout tiles by position
  whatever a pass holds.
- With the codes zeroed, the K rollouts' tables are identical under dropout.
- loss minus `fan_wta_weighted` equals the WTA-0 model's loss.
- The config composes and differs from lxfan4 by exactly a2's two keys.

Each key test was sabotaged once and failed
(`/home/wolfe/morph-scratch/credit/sabotage_b.log`). One sabotage runs all streams in
one pass under the code, and the mask, table and pass-count tests catch it.

**Still refused, by name:** a mixing or select fan under the code, `fan_seed_noise`, the
bare register, and the probe head with the fan. The cached and graphed decoders refuse
the fan.

**Measured on the way (a2 as well):** `fan/wta_ce` is NOT the table's per-slot minimum
(`fan/wta_oracle_ce`). The table writes stream i into EVERY slot. The grad pass writes
each slot's own winner, and a coda token also reads the earlier slots' cells. On the

**The three changes.** Each is bit-identical: the pins and every full tensor
(`pin_compare.py`, 1642 tensors, 0 differ).

1. **The gain hinge's two core applications are checkpointed on every model**
   (`_slot_gain_penalty`). Before this, only plan C (xHC) checkpointed them. Unchecked,
   each application keeps a whole core pass's activations until the backward. On LX-Fan's
   K*B rows x S*M cells that was the largest saved item: at batch 1, 1.80 GiB of lxfan4's
   4.87 and 2.82 of lxfan6's 6.58 (`_apply_core_step`). The backward now recomputes two
   core passes, which is the price the loop's own passes already pay.
   `tests/test_slot_gain_tail.py` counts the replays.
2. **The fixed-point term and the pass residual gather their slots before the fp32
   casts.** At full width, autograd kept an fp32 difference and denominator the size of
   the carrier for every pass. The numbers are the same, per slot, over the same elements.
3. **`_tul_core` gathers the slots from the BASE rows and tiles the gathered states.**
   `gather` saves its input, and on the tiled `xn` that input was a K-fold copy of the
   whole fp32 carrier (60 MiB per base row saved at M = 4).

`tests/test_tul_lx_credit.py::test_saved_bytes_do_not_regrow` pins the saved bytes on the
tiny model. Reverting any one change fails it
(`/home/wolfe/morph-scratch/credit/sabotage_mem.log`).

**Also changed for memory.** The WTA table runs one pass per stream (amendment above), so
its transient peak is one coda pass of the model's own size.

**What is left.** These items were not changed, and each is a real next lever:

- the coda's per-block checkpoint inputs, fp32 HC carriers (80 MiB per base row per
  block per coda call; 800 MiB per base row on lxfan4_wta, which runs two grad coda
  calls). Storing them in bf16 would change the numerics, so it was not done;
- the tied head `lm_weight()`. Every caller rebuilds it (a 192 MiB fp32 cat plus a 96 MiB
  log-map save per call; `_tul_fan_all` also pads a copy). This is constant in the batch,
  about 0.3 to 0.6 GiB per step.
