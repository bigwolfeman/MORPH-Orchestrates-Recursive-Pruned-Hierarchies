# Flat K/V kernels (K1) and PDL (P0) on the speed base at 5k

Status: planned

## Question

`model.kv_flat_kernels` (K1, merge d47486ef) re-tiles the CCA conv backward and the prologue rows
backward and sums the weight-grad partials in one fixed-order kernel. It changes the sum order,
so it is rounding only: gradient against key off, global relative difference 3.95e-3, which is
the bf16 error of either path against fp64. Pinned bench 164.12 -> 160.20 ms. `model.pdl` (P0)
prints the same byte-gate hash on and off and saves 0.5-0.95 ms. Does the speed base with both
keys on train the same function at 5k?

## Hypothesis

Both keys change rounding or timing only. The arm sits inside the seed spread of the G1 runs.

## Predictions

New arm: `nowta_pointer_fast_spdcells_speed_bf16c_cellp3` + `model.kv_flat_kernels=true
model.pdl=true`, seeds 1 and 2. Controls: the filed S5 + G1 runs on the same base, seed 1 CE@6
3.9023 / K1-K6 +0.0057, seed 2 3.9033 / +0.0067 (means 3.9028 / +0.0062;
`successes/2026-10-13-g1-triton-gemm-5k.md`).

|---|---|---|---|
| K1 + P0 on the speed base | 1 | 3.904 | +0.0058 |
| K1 + P0 on the speed base | 2 | 3.904 | +0.0058 |

- Decision: both keys go ON in `nowta_pointer_fast_spdcells_speed_bf16c` if the arm's mean CE@6
  minus 3.9028 is <= +0.003 AND its mean K1-K6 is >= 95 % of +0.0062 (>= +0.00589). If CE@6

  of the control. Below +0.0039: both keys stay off, and P0 alone (exact) is checked by the byte
  gate only, so K1 is the suspect.
- The cell knob survives: gap(1) mean <= +0.015 and gap(2) mean <= +0.003 (controls +0.0059 /
  +0.0001).
- Stability on both runs: grad-norm max/median <= 30, `tul/gain_est` inside 0.85-0.95 from step
  1000 to 5000.
- The trainer eval runs with PDL on and does not crash (not run before this check).
