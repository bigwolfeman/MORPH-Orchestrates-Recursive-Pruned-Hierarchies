# Planned: L3-WAKE — DB init, then standard AdamW full-BPTT to wake the loop

Status: planned
Date: 2026-08-30 (frozen before launch; queued behind the ladder analysis queue).
Config: `tul_l3wake.yaml` (= tul_l3 + db_loop:false + optimizer:adamw +
init_from tul-l3 step_4500). Wolfe's hypothesis, verbatim: "we may need to take
the diffusion block one and also do some standard adamw training to it to wake
up the loops."

## Question

tul-l3 (DB-shaped: detached carry, per-iteration local mux) reached the ladder's
2nd-best CE (4.3519 @4250) with a loop that is CE-INERT: forced depth 1 vs 6
moves token CE 3.8683 → 3.8684 (paired rows, core_depth_sweep smoke). Does a
phase of standard end-to-end training (full BPTT, AdamW, fresh optimizer, LR
schedule restarted) on top of the DB weights make the iterations earn CE?

## Reference numbers (fixed)

l3 final 4.4005 / @4250 4.3519, depth-inert (Δ ≤ 0.001 nats, 3-row smoke —
the 48-row sweep queued before this run supersedes it as the pre-wake curve).
l2cap @4250 4.3489, worth 0.146 climbing. l1-adamw @4250 4.5278, σ_max 1.92,
worth flat ~0.027. Coreless nomask 4.3102. Same-config CE replicate spread
0.030–0.036 nats (l1 vs l1-rep).

## Predictions (frozen)

- **PW1 (stability).** Completes with S1 clean (no run > 0.20 nats above running
  min for 2+ consecutive evals after step 1000; no NaN): 85%. AdamW held σ at
  1.9 in l1-adamw; the init is a trained model, not noise.
- **PW2 (the wake, binding).** Post-run depth sweep (same instrument, 48 rows)
  shows CE(depth 6) ≤ CE(depth 1) − 0.02 nats: 35%. My prior: full BPTT under
  AdamW never made iterations pay in l1-adamw; but DB init hands it a working
  single-pass core, which l1-adamw never had. FALSIFIER: if the post-wake curve
  stays flat (|Δ| < 0.01 nats), "DB init + standard training wakes the loop" is
  dead AS STATED and the wake recipe needs the cap or a different objective.
- **PW3 (CE).** val/ce_tokens @4250 ≤ 4.35 (beats l3's own 4500-step number —
  note this run has 4500 EXTRA steps on the same data schedule, so beating it is
  necessary-not-sufficient; the ladder CE column is not comparable and the arm
  is scored on PW2): 60%.
- **PW4 (worth).** worth_shuffle reaches ≥ 0.04 for 3+ consecutive evals incl.
  one of the last three: 30% (uncapped full-BPTT arms all failed this; the DB
  init may transfer its trained write).

## Method

1. Queued behind "ANALYSIS QUEUE COMPLETE" in the ladder queue log (worth
   profiles + 48-row depth sweep land first; the pre-wake depth curve for l3 is
   an INPUT artifact of this experiment).
2. Smoke: 12 steps, gated on the init_from load line and exit 0 — first
   campaign use of training.init_from (weights only, fresh optimizer, step 0).
3. Full run: panel flags (steps 4500, batch 6, seed 1, eval_every 250,
   grad_probe_every 1), wandb tul-l3wake.
4. Post-run, same GPU chain: core_depth_sweep on tul-l3wake/step_4500 (depths
   1–8, 48 rows) → tul_samples for the arm → prune checkpoints.
5. Artifacts to lab/experiments/results/2026-08-30-tul-l3-wake/.
